# Migrating from captions.js 1.x to 2.0

Most apps need one change: install `konva` next to `captions.js`. Everything
else below keeps working, or affects only code that used the removed parts.

## Breaking changes

- **Konva is a peer dependency.** Install it yourself: `npm install captions.js konva`.
  This keeps a single Konva in your bundle when your app uses Konva too.
  `@captionsjs/server` still brings its own.
- **`renderString` is removed.** Draw with `renderFrame` (below), or use
  `renderStylePreset` for preset thumbnails in the browser.
- **Built-in presets have no `id` and no `layoutSettings`.** Both fields are now
  optional on `StylePreset` and the renderer never read them. If your app stores
  presets by id or uses the layout hints, keep your own copy of those fields.
- **Preset covers moved.** `style.verticalCoverImg` of the built-in presets points
  to `https://captionsjs.dev/presets/<slug>.jpg`, generated by `pnpm previews`,
  instead of `cdn.shorty.plus`.

## Deprecated, still working

- **`renderFrame` takes an options object.** The positional form still works and
  is marked `@deprecated`:

  ```ts
  // 1.x
  renderFrame(settings, undefined, captions, time, [width, height], layer, height / 480);
  // 2.0
  renderFrame({ settings, captions, time, size: [width, height], layer });
  ```

  In the options form `scale` defaults to `height / 480`, the rule the browser
  overlay and the server use. The positional `toCoef` still defaults to 1.
  `layoutSettings` is gone from the options form; it was never read.

## Changes you will see

- **Line breaks move.** Lines break on measured text width instead of a letter
  count, identically in the browser and on the server at any size. Most presets
  break the same text in different places than 1.x.
- **Screens end at sentences, speaker changes and pauses** of 0.6 s or more, and
  a finished screen stays up for up to 1 s of silence.
- **A word too wide for the frame shrinks to fit** instead of running off it.
- **`*word*` in text inputs now shows**, when the preset's `expressiveness` is
  above 0 (default 0: no visible change).
- **`animation` accepts any registered effect name**: its type is
  `BuiltInAnimation | string`. Unknown names draw no animation instead of
  falling through silently.
- **The browser overlay follows video frames.** Where the browser supports
  `requestVideoFrameCallback`, captions change on the exact video frame
  (`mediaTime`), at most once per frame; elsewhere it keeps using
  `requestAnimationFrame`.
- **`sideEffects: false`** in `package.json`: bundlers can drop unused parts of
  captions.js.
